# Projects track the Reference Project through git history, synced by a Sync Loop

The Kit publishes its `reference/` directory as a `reference` branch (`git subtree split`). Scaffold seeds every Project from that branch so they share history. A daily Sync Loop in each Project merges the Kit's `reference` branch and opens a PR; every merge to the Kit's `master` is a release, there are no tags. Conflicts fall exactly on files the Project deliberately changed; the Loop resolves them by intent with `/resolving-merge-conflicts`, lists each resolved hunk in the PR, and labels it `ready-for-human`. Reference Project commits needing manual steps carry an `Upgrade:` line, which the Loop copies into the PR. Rejected: agent-driven 3-way patching (reinvents git merge) and versioned `@kit/*` packages (right for pieces that stabilise later, premature now).

Amended by ADR 0009: the Sync Loop is not daily and does not run in CI. It is the `sync-loop` skill, which the owner runs in a Project checkout when they want the Reference Project's latest; everything else here — the merge, the resolution by intent, the hunk list, the `Upgrade:` lines, `ready-for-human`, never merging — is unchanged.
